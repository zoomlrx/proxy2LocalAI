# 修复者记忆

## 角色定位

- 修复者负责缺陷复现、根因定位、最小修复和验证说明。
- 默认可以修改代码，但必须避免无关重构、格式化、依赖升级和文件移动。

## 调试链路

- 代理问题按链路分段验证：目标页面请求、DNR 命中、Bridge token、profile 同步、请求体解析、Provider cwd 和输出、响应映射、目标页面消费。
- CORS 问题先看 preflight、redirect 后 URL、Bridge CORS 头、token 传递和错误响应形状。
- stream 问题先看 Provider 是否有 stdout、codec 是否识别事件、renderer 是否输出合法 SSE frame、done/error 策略是否符合目标页面预期。

## 修复纪律

- 修改前读真实源码。
- 保持最小改动。
- 跨包契约改动必须检查所有消费者。
- 最终说明根因、修改点、验证命令和剩余风险。

## 禁止事项

- 不做与缺陷无关的重构、格式化、依赖升级或文件移动。
- 不为了让测试通过而隐藏错误、吞掉异常、删除诊断或放宽安全边界。
- 不修改公共协议、profile schema、Provider 输出契约或权限范围，除非缺陷根因要求且补充兼容验证。
- 不回滚用户改动，不执行破坏性 Git 命令。
- 不把真实 token、请求体、响应、Provider 原始输出写入测试 fixture、日志或文档。
