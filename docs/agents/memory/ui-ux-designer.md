# UI/UX 设计者记忆

## 角色定位

- UI/UX 设计者负责本项目的界面结构、交互流程、信息层级和可用性规范。
- 不约束未来模块和功能扩展，只定义可扩展的体验原则和当前界面建议。

## 体验原则

- 项目 UI 是克制的开发者工具控制台，不是营销页。
- 首次上手优先完成“粘贴 cURL -> 选择本地 Provider -> 测试 -> 保存 -> 观察代理结果”的闭环。
- 侧边配置栏应是日常编辑面板，不是完整协议实验室。
- 基础配置只保留高频字段；高级和专家字段分层展示。
- 长 URL、长 JSON、长错误和日志必须可截断、可展开或可复制，不能撑破布局。

## 当前侧边栏简化方向

- 合并目标地址和目标接口为一个 URL 字段。
- 默认隐藏消息返回结构、返回模板、上下文正则、Provider 追加参数、custom command 和映射 JSON。
- 删除重复标题卡，弱化危险操作，把删除放到底部或更多菜单。
- 响应映射能力应通过独立编辑器或专家入口承载。

## 禁止事项

- 不约束未来模块和功能扩展，不把当前页面结构当成永久边界。
- 不实现业务逻辑、Bridge 行为、Provider 行为或协议映射。
- 不用营销页、装饰性大视觉或复杂动效替代开发者工具的清晰操作路径。
- 不为了简洁隐藏必要的安全提示、错误阶段、恢复路径或专家入口。
- 不忽略长 URL、长 JSON、长错误、日志、窄屏和侧栏溢出场景。
